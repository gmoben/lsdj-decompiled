## Toolchain origin

LSDj is written in C and built with a **modified GBDK 2.95** (see References in
`README.md`). Expect compiler-emitted patterns: the SDCC/GBDK calling
convention, `__sdcc`-style runtime helpers, banked-call trampolines, and library
routines from `crt0`/`libc`. Recognising these idioms is the fastest way to
label large stretches of the disassembly.

## Bank map

Full per-bank breakdown in [`bank_map.md`](bank_map.md) (generated by
`tools/bankmap.py`). High-level:

| Banks | Contents | Status |
|-------|----------|--------|
| `$00` | entry, vectors, init, dispatch, song access, sound/sync | **disassembled** (`src/bank00.asm`) |
| `$01`-`$07` | engine/program code + data | INCBIN |
| `$08`-`$1A`, `$20`-`$21` | **21 sample kits** (TR-808, TR-909, … — confirmed) | INCBIN (data) |
| `$1B`-`$1F` | more program code | INCBIN |
| `$22`-`$3F` | empty (`$FF` fill) — spare room for user kits | INCBIN |

Roughly half the 1 MiB ROM is used; the upper banks are blank, which is why
LSDPatcher can add custom kits. See [`data_model.md`](data_model.md) for the
song format and [`save_format.md`](save_format.md) for the `.sav`/kit formats.

## Bank 0 notes

Disassembled with `tools/disasm.py` (header `$104`-`$14F` marked as data).
Named entry points: `Entry` (`$100`), the five interrupt vectors, and
auto-generated `Lxxxx` labels at branch/call targets.

### Structure

Bank 0 is almost entirely **compiled C** (SDCC/GBDK): ~211 `ret`s (functions),
291 direct `call`s, and the SDCC stack idiom `ld hl, sp+N` (`f8 0N`) is
everywhere. Control is dispatched through **16 `jp hl` sites** (jump tables /
`switch`), which is why it is kept as full linear disassembly: recursive-descent
tracing (`--trace`) cannot follow computed jumps and would mislabel
dispatch-reached functions as data. Understanding these `jp hl` jump tables is
the key to mapping bank 0's call graph. There is also a small bit-mask table at
`$0010` (`80 40 20 10 08 04 02 01 01 02 04 08 10 20 40 80`).

See [`functionality.md`](functionality.md) for the recovered behaviour
(interrupt model, sound/sync/input/LCD engines, banking, RAM map). Named
routines live in `src/bank00.sym`.

### Boot / init (`$0150`, reached via `jp` from `Entry`)

```
di
ld d, a / ld e, b        ; preserve boot regs (A = CGB/DMG id, B = AGB id)
xor a
ld sp, $e000             ; stack at top of WRAM
ld hl, $dfff / clear...  ; zero WRAM  $C000-$DFFF (0x2000 bytes)
ld hl, $ffff / clear...  ; zero HRAM  $FF80-$FFFF (0x80 bytes)
ld [$cbd9], a <- d       ; save boot A (hardware id) to WRAM $CBD9
ld [$cbda], a <- e       ; save boot B (GBA flag)   to WRAM $CBDA
call $349b               ; (next: identify/continue init)
xor a / ldh [rSCY],[rSCX],[rSTAT],[rWY],a   ; reset scroll/LCD status/window
...
```

WRAM `$CBD9`/`$CBDA` therefore hold the CGB/AGB detection bytes — candidates for
`constants/` symbols once confirmed.
