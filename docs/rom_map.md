# LSDj 9.4.0 ROM map

Living document of reverse-engineering findings: cartridge identity, memory
layout, and where things live. (The disassembly itself, `src/*.asm`, is
generated from your ROM + the tracked `src/bankNN.sym` maps — see `README.md`.)

## Toolchain origin

LSDj is written in C and built with a **modified GBDK 2.95** (see References in
`README.md`). Expect compiler-emitted patterns: the SDCC/GBDK calling
convention, `__sdcc`-style runtime helpers, banked-call trampolines, and library
routines from `crt0`/`libc`. Recognising these idioms is the fastest way to
label large stretches of the disassembly. The "modified" part has turned out to
be extra peephole rules on top of GBDK 2.95-3's SDCC 2.2.1 — recovered well
enough to compile six functions back to identical bytes
([`toolchain.md`](toolchain.md)). Not everything is C: bank `$02`'s sequencer
core and bank 0's interrupt handlers, sound tick, envelope/pitch steppers and
tile loader (~200 functions, ~15 KB) are hand-written assembly
(`tools/match/code_kind.py`).

## Bank map

Full per-bank breakdown in [`bank_map.md`](bank_map.md) (generated by
`tools/bankmap.py`). High-level:

| Banks | Contents | Status |
|-------|----------|--------|
| `$00` | entry, vectors, init, dispatch, song access, sound/sync | **disassembled + named** (`src/bank00.sym`) |
| `$01` | UI string table, help text, crash screen, UI helpers | **disassembled + named** |
| `$02` | sound engine: sequencer, FX commands, instruments | **disassembled + named** |
| `$03`-`$07` | editors: Instrument, Phrase, Table, Chain/Wave/Word, Song | **disassembled + named** |
| `$08`-`$1A`, `$20`-`$21` | **21 sample kits** (TR-808, TR-909, … — confirmed) | INCBIN, labeled per kit + sample at build time |
| `$1B`-`$1F` | Project/Help, File + save/load, Groove/Synth, screen pre-draw + graphics, instrument subsystem | **disassembled + named** |
| `$22`-`$3F` | empty (`$FF` fill) — spare room for user kits | INCBIN |

Roughly half the 1 MiB ROM is used; the upper banks are blank, which is why
LSDPatcher can add custom kits. See [`data_model.md`](data_model.md) for the
song format and [`save_format.md`](save_format.md) for the `.sav`/kit formats.

## Bank 0 notes

Disassembled with `tools/disasm.py` (header `$104`-`$14F` marked as data).
Every function has a real name (`src/bank00.sym`); internal branch targets are
function-local labels (`.loop`, `.done`, …), and even the `$FF` filler in the
RST/interrupt vector page carries per-byte `UnusedXXXX` symbols so debuggers
show no auto-labels.

### Structure

Bank 0 is almost entirely **compiled C** (SDCC/GBDK): ~211 `ret`s (functions),
291 direct `call`s, and the SDCC stack idiom `ld hl, sp+N` (`f8 0N`) is
everywhere. Control is dispatched through **16 `jp hl` sites** (jump tables /
`switch`). The first carve kept bank 0 as full linear disassembly because a
plain recursive-descent trace couldn't follow them; the bank-aware coverage
trace (`tools/coverage.py`) now resolves the tables, and `carve_clean.py` only
marks bytes as data when they are both unreached and data-like. The bit-mask
table at `$0010` (`80 40 20 10 08 04 02 01 01 02 04 08 10 20 40 80`) is
`BitMasks`, with per-byte names (`BitMaskBit6`…, `BitMasksAsc`…).

See [`functionality.md`](functionality.md) for the recovered behaviour
(interrupt model, sound/sync/input/LCD engines, banking, RAM map). Named
routines live in `src/bank00.sym`.

### Boot / init (`$0150`, reached via `jp` from `Entry`)

```
di
ld d, a / ld e, b        ; preserve boot regs (A = CGB/DMG id, B = AGB id)
xor a
ld sp, $e000             ; stack at top of WRAM
ld hl, $dfff / clear...  ; zero WRAM  $C000-$DFFF (0x2000 bytes)
ld hl, $ffff / clear...  ; zero HRAM  $FF80-$FFFF (0x80 bytes)
ld [wBootHwId], a <- d   ; save boot A (hardware id), $CBD9
ld [wBootAgbId], a <- e  ; save boot B (GBA flag),    $CBDA
call display_off         ; GBDK library routine ($349B)
xor a / ldh [rSCY],[rSCX],[rSTAT],[rWY],a   ; reset scroll/LCD status/window
...                      ; -> InitAndLoadSong ($0DDB) -> main.mainLoop ($1377)
```

`wBootHwId`/`wBootAgbId` (`$CBD9`/`$CBDA`) hold the CGB/AGB detection bytes.

## Banks $1D/$1E: synth rendering

The matching C in `c/bank1d/SynthScreen.c` covers the two weighted waveform
mixers (`$4D81`, `$5190`), composition/distortion (`$5323`), and shape
dispatch (`$5695`). `LoadSynthShape` in bank 0 temporarily selects bank
`$1E` and sign-extends a 32-byte seed cycle into the 32-word accumulator
`wSynthShapeBuf` (`$C9F4`). The mixers add signed correction samples from
bank `$1D`: `SynthShapeTableA` at `$4EF0` for signal types 0/1, or
`SynthShapeTableB` at `$50F0` for type 2.

The dispatcher selects these bank-$1E seed-table bases:

| Symbol | Address | Wave shape / signal type |
|--------|---------|--------------------------|
| `SynthSeedTableA` | `$71EC` | 0 / 0 |
| `SynthSeedTableB` | `$73EC` | 0 / 1 |
| `SynthSeedTableC` | `$74EC` | 1 / 0 |
| `SynthSeedTableD` | `$76EC` | 1 / 1 |
| `SynthSeedTableE` | `$77EC` | 0 / 2 |
| `SynthSeedTableF` | `$78EC` | 1 / 2 |

`SynthWaveTables` at `$720C` is an interior name for the second cycle of
`SynthSeedTableA`. Shape 2 clears the accumulator before mixing; shape 3
uses the fixed offsets A + `$F0`, B + `$70`, or E + `$70`.

Two additional 16-byte per-frame curves are now named: `wSynthCurveAmp`
(`$CA94`), interpolated from synth parameter 2's nibbles, and
`wSynthCurveLimit` (`$CAA4`), interpolated from parameters 13/14 after adding
`$0F`. Composition uses the latter to set its window. The byte historically
named `wSynthFilterParam` (`$C9EE`) selects **CLIP / FOLD / WRAP** (0/1/2),
rather than resonance; the actual filter dispatch follows composition.

The full parameter redraw is `DrawSynthNumber` at `$1D:$65C2`; its two
hidden-field `--` strings are at `$68A5`/`$68A8`. `OverwriteSynthWaves`
at `$6D6F` opens the overwrite confirmation and sets `$CB61`/`$CB62` flags;
it does not itself write wave data. The dialog's text uses bank 0's
`AsciiCharMap` (`$086F`, with `wStringSrc` biased by -`$20`) and
`IdentityCharMap` (`$08C8`) for its border tiles.
